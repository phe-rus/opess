# AGENTS.md

## What this is

`opess` — a web-based desktop/OS UI (wallpaper, taskbar, draggable windows, widgets) built with **TanStack Start** (file-based routing, SSR) + React 19 + Tailwind v4. Single package, no monorepo.

## Build approach

Tracer Bullet (prove the whole pipe end to end, then thicken it one strand at a time).

## Commands

- Install: `bun install` — **Bun is the package manager** (`packageManager: "bun"`, `bun.lock`). Don't use npm/yarn/pnpm.
- Dev: `bun --bun run dev` — Vite dev server on **port 3000**, bound to all addresses (`server: { host: true }` in `vite.config.ts`), so it is reachable on the LAN.
- Build/preview: `bun --bun run build`, `bun run preview`.
- Regenerate route tree: `bun run generate-routes` (runs `tsr generate`); the TanStack Start Vite plugin also regenerates it on dev/build.
- **There is no test, lint, or format tooling in this repo** — don't guess `bun run lint`/`test`. The only verification step is typecheck: `bunx tsc --noEmit` (passes cleanly; run this before considering a change done). `test-preferences.json` records this as a deliberate gate (`tool: null`, `gate: typecheck+verify`) so `/test` and `/check review` know it is intentional; behavior is confirmed by `/check verify`, not a test suite.

## Generated / do-not-edit

- `src/routeTree.gen.ts` is generated by TanStack Router — never hand-edit (`.vscode/settings.json` marks it readonly). Add routes as files in `src/routes/` instead.

## Architecture notes (not obvious from filenames)

- Route group `src/routes/(container)/route.tsx` is the **desktop shell**: it renders `Wallpaper`, `Taskbar`, the `WindowsProvider`, and the right-click context menu around the `Outlet`. Desktop home (widgets + window rendering) is `src/routes/(container)/index.tsx`.
- Window management is local React state, not routing: `src/components/windows-manager/` exposes `WindowsProvider`/`useWindows` (`context.ts` = types, `provider.tsx` = state, `windows-frame.tsx` = window chrome). Windows are `WindowConfig` records keyed by id.
- **Apps are registered by hand** in the `APPS` array in `src/components/windows-manager/apps.tsx` (`AppEntry` records: id, name, Hugeicons icon, `content`; `useAppLauncher` opens and toggles them). `taskbar.tsx` only renders `APPS`. New app UI goes in `src/components/apps/` and is wired in there; the `messages` app is still placeholder content.
- Server-side data must go through `createServerFn`: `src/hooks/use-system.ts` wraps `src/lib/storage.ts`, which imports Node-only `systeminformation`/`os`. **Never import `src/lib/storage.ts` into a client component directly** — call the server fn via the exported TanStack Query `queryOptions` (see `useSystemOptions`, consumed with `useSuspenseQuery` in the storage widget).
- `src/lib/files.ts` is a second server-only module (`node:fs`/`os`): `src/hooks/use-files.ts` wraps `ListDirectory`/`ReadTextFile` in `createServerFn` and exposes `directoryOptions`/`filePreviewOptions`. **Never import `src/lib/files.ts` into a client component either**; the File Manager app consumes those query options.
- The **data & config store** (spec 0001) is the third server-only module: `src/lib/store/` owns all durable state (settings, account, desktop, apps, and the encrypted `secrets.enc`), writing versioned JSON files atomically (dir 0700, files 0600) under one config directory. `src/hooks/use-store.ts` wraps it in `createServerFn` + TanStack Query options (`getSettings`/`updateSettings`, `getDesktop`/`updateDesktop`, `listApps`/`upsertApp`/`removeApp`, `getAccount`, `getConfigLocation`); `readSecrets`/`writeSecrets` stay server-only. **Never import `src/lib/store` into a client component.** Config dir from `OPESS_CONFIG_DIR` (default `<home>/.config/opess`); the AES-256-GCM key file from `OPESS_SECRET_KEY_FILE` (default `<configDir>/secret.key`).
- Router + Query SSR integration is wired in `src/router.tsx` (`setupRouterSsrQueryIntegration`); the QueryClient context comes from `src/lib/tanstack-query/root-provider.tsx`.
- Only `weather.tsx` is still mocked (hardcoded "72°F Sunny in San Francisco"). The real metrics pipeline (`useSystemOptions`) now feeds the storage widget, the system usage widget, and the Settings app.
- The Settings app (`src/components/apps/app-settings/settings.tsx`) is the other real metrics consumer: it reads system data via `useSystemOptions` and network data via `useNetworkOptions` (the `getNetworkInfo` server fn, also in `src/hooks/use-system.ts`). It also owns the Appearance **theme picker** (`ThemeCard`) and a **Data** section showing the resolved config directory and key file (`configLocationOptions`).
- Theme: `src/components/theme/` (`ThemeProvider`/`useTheme`) reads the `appearance.theme` setting from the store (`light` | `dark` | `system`, default `light`; `system` follows the OS via `useMediaQuery`), and `src/routes/(container)/route.tsx` mounts it and toggles the `dark` class on the desktop root.
- Wallpapers: `src/components/wallpapers/context.tsx` holds `WallpaperProvider`/`useWallpaper` and the `WALLPAPERS` list; the desktop shell and the Settings wallpaper section both read it.
- Widget layout: widgets are dragged and resized on desktop by `WidgetDock` (`src/components/widgets/widget-dock.tsx`); `src/hooks/use-widget-dock.ts` persists each position/size in `localStorage` under `opess.widget-dock` (double click a docked widget to reset). The hook comments mark where the two load/persist effects swap to API calls later.

## Toolchain quirks

- **React Compiler is active** (babel preset in `vite.config.ts`); components must follow the React hook rules.
- **Tailwind v4 is CSS-first**: no `tailwind.config` — theme, `@utility`s, and variables live in `src/globals.css`.
- shadcn-style UI in `src/components/ui/`, configured by `components.json`: style `base-mira`, **icon library is `hugeicons`** (not lucide), CSS variables enabled.
- Path alias `@/*` → `src/*` (tsconfig `paths`; Vite resolves via `resolve: { tsconfigPaths: true }`).
- `tsconfig.json` is strict with `noUnusedLocals`/`noUnusedParameters` (unused imports fail typecheck) and `verbatimModuleSyntax` (use `import type` for types).
- `README.md` is TanStack starter boilerplate and partly stale: it references `src/styles.css` and `src/routes/demo/`, which don't exist (the stylesheet is `src/globals.css`). Trust the code over the README.
